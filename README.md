# アップローダー

uploader.jp のような番号付きファイル一覧と、ブラウザーからのアップロード・ダウンロードができる日本語のアップローダーです。管理画面はありません。ファイル本体はD1のBLOBに保存し、R2などの外部ストレージは使いません。

外部ツール向けのAPI仕様は [API.md](./API.md) を参照してください。

## 実装済みの範囲

- 1ファイル最大100MiB（104,857,600バイト）、全体の保存予約上限400MiB（419,430,400バイト）。サイズ表記は1024単位のKiB/MiBで統一
- ファイル名・コメント・サイズ・日時・ダウンロード数の一覧
- 投稿時に任意のダウンロードパスワードと削除キーを設定
- パスワード付きのファイルには一覧に鍵マークを表示
- 一覧からファイルを削除可能（削除キーを設定した場合はキーの入力が必要）
- 保存予約容量をプログレスバーで表示
- 64KiB単位の分割アップロードと、256KiB単位の分割ダウンロード
- 未完了のアップロードは24時間後に次のアップロード開始時に削除
- ダウンロードは添付ファイルとして配信し、HTMLなどをブラウザー上で実行しない
- `/api/v1` とPython標準ライブラリによるCLI（一覧・取得・投稿・削除）

アップロード中の容量も予約に含めます。全体上限は試験用の値です。D1の無料データベース上限は500MBで、テーブル・インデックス等もその容量に含まれるため、オーバーヘッドの余裕を見て上限を400MiBにしていますが、保存できる保証はありません。D1側の上限に先に達した場合はエラーになります。

## パスワードと削除キー

アップロード時にどちらも空欄のままにできます。ダウンロードパスワードが空欄なら誰でもダウンロードでき、削除キーが空欄なら誰でも削除できます。ダウンロードパスワードを設定していても、削除キーが空欄なら誰でも削除できます。既存の投稿にもパスワードや削除キーは自動設定されないため、削除キーのない既存ファイルも誰でも削除可能です。削除キーを忘れた場合の復旧機能はありません。

パスワードと削除キーは平文ではなく、個別のソルトを使ったPBKDF2-SHA-256で保存します。ダウンロードの認証後は、24時間有効なファイル専用トークンを各分割リクエストに送ります。パスワードと削除キーは十分に長く推測されにくいものにしてください。パスワードはアクセス制限であり、ファイル本体は暗号化されません。認証の試行回数はファイル・操作ごとに1分間10回までで、成功時にはその制限をリセットします。複数の利用者による試行も同じ枠に数えられます。

## ローカルで試す

Node.jsとnpmが必要です。先に下の「Cloudflareへデプロイ」の手順でD1を作成し、マイグレーションを適用してください。

```sh
npm run dev
```

この設定は `remote: true` のため、ローカル実行でも**自分のCloudflareアカウントの実際のD1**を使います。試したデータはそのD1に保存されます。Wranglerが表示するURLをブラウザーで開き、100MiBを試す前に、小さなファイルからアップロードとダウンロードを確認してください。

## Cloudflareへデプロイ

`uploader/` ディレクトリで、まず依存パッケージをインストールします。npmのスクリプトはローカルにインストールされたWranglerを使います。

```sh
npm install
```

設定ファイルは `wrangler.example.jsonc` をコピーして作ります。`wrangler.jsonc` は各自の環境固有の設定（D1のID）を含むため、`.gitignore` で除外しています。

```sh
cp wrangler.example.jsonc wrangler.jsonc
npx wrangler login
npx wrangler d1 create uploader-db
```

`d1 create` が表示した `database_id` を、`wrangler.jsonc` の `YOUR_D1_DATABASE_ID` と置き換えます。binding名は `DB` のままにしてください。続けてマイグレーションの適用とデプロイを行います。

```sh
npm run db:apply:remote
npx wrangler deploy
```

Worker名は `uploader` で、デプロイ後のURLは `https://uploader.<アカウントのサブドメイン>.workers.dev/` になります。Worker名やD1名を変えた場合は、`package.json` のスクリプトや [ADMIN.md](./ADMIN.md) のコマンドも読み替えてください。

更新時も、**先にマイグレーションを適用してから**デプロイしてください。`0002_file_passwords.sql` はパスワード用の列などを、`0003_api_uploads.sql` はAPIのアップロード認証用の列を追加します。既存のファイルは保持されます。

なお、公開中のアップローダーを運用している環境でローカル実行すると、本番のD1にテストデータが書き込まれます。運用中は `wrangler dev` を使わないか、`remote` を外した別設定で実行してください。

## Python CLI

Python 3の標準ライブラリだけで実行できます。URLにはアップローダーのオリジンを指定します。

```sh
python3 uploader.py --url https://example.workers.dev
```

`--url` を省略すると、次の順に既定のURLを探します。

1. 環境変数 `UPLOADER_URL`
2. `~/.config/uploader/config.json`（`{"url": "https://example.workers.dev"}`。`XDG_CONFIG_HOME` が絶対パスならそちらを使用）
3. `~/.uploader`（URLを1行だけ書いたファイル、または上と同じJSON）

[sample.uploader](./sample.uploader) を `~/.uploader` にコピーしてURLを書き換えると使えます（`#` で始まる行はコメント）。

`--url` を指定した場合はそれが最優先です。コンソールの `url` で現在のURLを表示し、`url https://example.workers.dev` で接続先を切り替えて `config.json` に保存できます（接続確認後に保存。ファイルは `0600`、ディレクトリは `0700`）。保存するのはURLのみで、パスワード・削除キー・トークンは保存しません。

対話コンソールでは次のコマンドを実行できます。空白を含むファイル名は `"my file.zip"` のように引用してください。

```text
uploader> list
uploader> put example.zip
uploader> get 12
uploader> get 12 saved.zip
uploader> delete 12
uploader> url
uploader> !ls -l
uploader> help
uploader> quit
```

`!` に続くコマンドは**サーバーではなく自分のPCのシェルで実行**されます。`!` だけならローカルシェルを起動します。`!cd` は子シェル内だけの変更なので、コンソールの作業ディレクトリは変わりません。`quit`・`exit`・`bye` または Ctrl+D で終了します。従来どおり `python3 uploader.py --url https://example.workers.dev list` のように単発実行することもできます。

投稿時のコメント、パスワード、削除キーは対話入力します。パスワードと削除キーは**入力した文字がそのまま画面に表示され**、端末の履歴にも残り得るため、周囲に注意してください。アップロード・ダウンロードの進捗は、端末では79文字以内の1行を書き換えて（バー・割合・チャンク数・速度・ETA・転送量。幅が狭いと後ろから省略）表示し、端末以外（パイプ・ファイル）では10%刻みの行を追加します。空の削除キーでは誰でも削除できます。取得先の既存ファイルは上書きしません。保存したファイルの権限は `umask` に従います（通常 `rw-r--r--`）。削除時は番号から解決したUUIDとファイル名を表示し、確認後にそのUUIDを削除します。HTTPSを必須とし、ローカルホストのみHTTPを許容します。認証情報の漏洩を避けるためリダイレクトには追従しません。

投稿開始や削除の応答が失われた場合は自動再送せず、操作結果を一覧などで確認してください。失敗した開始要求の予約が残った場合は期限切れ後、次の投稿開始時に回収されます。

`workers.dev` のBrowser Integrity CheckでPython標準のUser-Agentが拒否される場合があるため、CLIは自身を `uploader-cli/1.0` として識別します。Cloudflare側の拒否が続く場合は、エラー表示とCloudflareのセキュリティ設定を確認してください。

## 実測時の注意

Workers無料プランのCPU時間は1リクエストあたり10msです。ファイルを小さなリクエストに分けているのは、この制限下でD1のBLOB変換が実用になるかを測るためです。大きなファイルほどHTTPリクエスト数が増えます。100MiBではアップロード1,600回、ダウンロード約400回のチャンク要求になります。CPU超過やメモリ超過はWorkerのエラー（例：1102）になり、アプリ側で通常のエラーメッセージに変換できない場合があります。

D1には1行2,000,000バイト、1クエリ結果50MB、無料枠で1 Worker呼び出しあたり50回のクエリなどの制約もあります。チャンクサイズや処理時間はローカルだけで判断せず、Cloudflareへデプロイした環境でWorkers Logsを見ながら確認してください。

パスワードのハッシュ計算と認証もWorkersのCPU時間を使います。無料枠の実環境で、パスワードと削除キーを両方設定したアップロード、認証、削除のCPU時間を確認してください。ローカルで成功しても無料枠での動作は保証されません。

`npm test` は一時ディレクトリ内のローカルD1を使い、既存データの移行、画面API・v1 APIとPython CLIの基本操作を確認します。設定済みのリモートDBには接続しません。

## 未実装・運用上の制約

- 管理画面、通報、利用者認証はありません。
- 公開すると誰でもアップロードでき、削除キーがないファイルは誰でも削除できます。悪用対策・管理手段・利用ルールが整うまでは、公開サービスとして運用しないでください。
- 未完了アップロードの削除は、新しいアップロード開始時にのみ行います。長期間アクセスがなければ期限切れデータが残ります。
- D1の保存上限やWorkerの日次上限に達した場合、アップロード・一覧・ダウンロードが失敗することがあります。
